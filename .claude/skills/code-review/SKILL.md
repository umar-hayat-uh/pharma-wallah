# Code Review

## Purpose
Review changes to PharmaWallah for correctness, consistency with the repo's established patterns,
and the specific mistakes this codebase makes repeatedly.

## Trigger Examples
- "review this change"
- "review the diff"
- "does this follow our patterns?"
- before reporting done on any implementation task (self-review)

## Read First
1. `git diff` / `git diff --staged` — the actual change.
2. `CLAUDE.md` §6 Engineering Rules.
3. `.claude/MEMORY.md` §3 (authorization) and §8 (gotchas).

## Architecture Context
Two authorization models, three data stores, several hand-maintained registries, and a lot of
near-duplicate code. Most defects here are not logic errors — they are **a missing ownership
filter, a missing registry entry, or the wrong client**.

## Procedure
1. **Read every hunk.** Not the summary, the diff.
2. **Authorization — first and most important.**
   - Service-role client used? Then every query needs the ownership filter. Trace it.
   - Did the change switch a route between anon/RLS and service-role? That is a security change;
     it must be deliberate and called out.
   - Admin route? `ADMIN_EMAILS` checked?
3. **Input validation.** Every new param parsed, type-checked, clamped against a `MAX_*`.
   Enums checked against an allow-list. JSON parse in try/catch → 400.
4. **Correct store and client.** Supabase vs mongoose (`pharmawallah`) vs root native client
   (`pharmacopedia`) vs Redis. Wrong Mongo client = empty results, no error.
5. **Cache coherence.** New write path to cached data → is the cache invalidated? New cache key →
   does it have a TTL and a namespace matching `MEMORY.md` §4?
6. **Error handling matches the repo.** `NextResponse.json({ error }, { status })`. Redis and
   external calls wrapped so they **fail open**. Auth **fails closed**.
7. **Registry updated?** New calculator → an entry in its subject in `tool-index.ts`, slug matching a real page. New subject
   → `SUBJECTS`. New protected route → `PROTECTED_PATHS`.
8. **Reuse.** Is this a fifth copy of something? The admin allowlist and the entry-type maps are
   already duplicated — do not add a third or fourth instance of anything.
9. **Consistency with the neighbour.** Naming, file layout, `"use client"`, icon library, motion
   library, comment density. A change that reads foreign is a finding.
10. **Hygiene.** No `console.log` debris, no commented-out blocks, no edits to generated files
    (`public/sw.js`, `public/workbox-*.js`, `next-env.d.ts`), no secrets, no scope creep.
11. **Baselines.** `npx tsc --noEmit` still 0 errors.

## Files Usually Involved
The diff, plus the nearest-neighbour file the change should resemble.

## Security Checks
- [ ] Ownership filter on every service-role query.
- [ ] No client-supplied id used as authorization.
- [ ] Auth checked before any mutation; 401 returned.
- [ ] Admin allowlist checked on admin routes.
- [ ] Rate limiting on anonymous / expensive / paid endpoints.
- [ ] Answer keys stripped from scored payloads.
- [ ] Scores computed server-side, never read from the request body.
- [ ] Mongo regex input escaped.
- [ ] No secret in a `NEXT_PUBLIC_*` var, in code, in a log, or in the diff.
- [ ] Service-role client not imported from a client component.

## Validation
Confirm each validation claim by reading the code, not the comment above it.

## Tests & Verification
```bash
npx tsc --noEmit    # baseline 0 errors
npm run build       # if the change touches config, routes, or imports
```
**No tests exist — never write "tests pass".** **Lint does not run — never write "lint clean".**
If you did not exercise the page, say so.

## Common Failure Modes
- **Approving a service-role query with no ownership filter.** The highest-severity miss possible
  here, and it looks like ordinary code.
- **Missing that a new file is unreachable** because no registry lists it.
- **Missing a cache invalidation** on a new write path.
- **Accepting a new inline rate limiter** instead of the shared ones.
- **Nitpicking style while missing an authorization change.** Rank findings by severity.
- **Flagging `public/sw.js` churn as a problem** — it is regenerated by every build.

## Do Not
- Do not rewrite the code during a review — report findings; apply fixes only if asked.
- Do not report a finding you have not verified by reading the file.
- Do not pad the review with generic advice.

## Update Project Knowledge
If the review uncovers a recurring mistake, add it to `.claude/MEMORY.md` §8 or to the relevant
skill's Common Failure Modes so the next session avoids it.
